## Updating flake inputs

Update one input per PR with `nix flake update <input>`, review `flake.lock`, and build the native no-link closure before pushing; `.github/workflows/evaluate.yml` gates both native host closures. An `llm-agents` update can change Pi, Herdr, and OpenCode together, so inspect all three selected versions.

## Packaging firstmate CLIs

`packages/external-tools.nix` builds the kunchenguid firstmate tools (`no-mistakes` + the five `*-axi` npm CLIs) as Nix derivations, exposed as the `pkgs.firstmate` overlay.

- `no-mistakes` is `pkgs.buildGoModule` from the pinned GitHub tag; `subPackages = ["cmd/no-mistakes"]` is required (root package is test-only).
- Each `*-axi` is `pkgs.buildNpmPackage` from the immutable npm registry tarball (prebuilt `dist/`; `dontNpmBuild = true`). To bump one, regenerate its lockfile with `npm install --package-lock-only --ignore-scripts` on the extracted tarball, replace `packages/firstmate/lockfiles/<pkg>.package-lock.json`, and update `version`, `tarballHash`, `npmDepsHash` (obtainable from the FOD hash-mismatch error, or `nix run nixpkgs#prefetch-npm-deps`).

## Packaging pi-web

`pkgs.pi-web` packages `@jmfederico/pi-web` with its vendored lockfile at `packages/pi-web/lockfiles/`; see `packages/external-tools.nix` for details.

- `mkNpmTool` takes `npmName`, `homepage`, `nodejs`, and `npmDepsFetcherVersion`; the `pkgs.nodejs` default keeps existing `*-axi` packages on node 24, while `pi-web` pins `nodejs_22` (engine >= 22.19; node 22 is what home.nix installs).
- pi-web needs `npmDepsFetcherVersion = 2`: the `@earendil-works/pi-coding-agent` dev dep ships an `npm-shrinkwrap.json`, and `npm ci` resolves its nested dev deps from packuments, which fetcher v1 (tarballs only) doesn't cache.
- The lockfile generated by `npm install --package-lock-only` omits `integrity` for the 6 nested `@earendil-works/*` deps under `pi-coding-agent`'s shrinkwrap. Patch those `integrity` values in from the registry (`dist.integrity`) before prefetching, or `prefetch-npm-deps` fails with "non-git dependencies should have associated integrity".
- `node-pty` ships no linux prebuilds, so `npm rebuild` (run by `npmConfigHook`) compiles its binding with node-gyp; the built `pty.node` ends up in `node_modules/node-pty/build/Release/`.
- Runtime: `pi-web`/`pi-web-server`/`pi-web-sessiond` come from the prebuilt `dist/` (`dontNpmBuild`); `pi-web install` installs a per-user systemd service on 127.0.0.1:8504 (a post-install user action, not baked into the derivation). Verify with `pi-web doctor`.
